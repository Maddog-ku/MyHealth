# MyHealth Feature Roadmap

本文件記錄已選定的下一階段功能：健康週報進階化、整合目標系統、食物資料庫與常用餐點、運動計畫生成、進度儀表板、成就/streak、照片辨識餐點流程。

## Phase 1：健康計畫與 Dashboard 核心

目標：先把現有資料串成單一產品主線。

- 新增 `GET /health-plan` 聚合 API，整合熱量預算、體重目標、訓練目標與 streak。
- Dashboard 顯示「今日健康計畫」摘要與下一步建議。
- 新增 `GET/PUT /health-plan/settings`，讓主目標、體重目標與每週訓練目標有單一設定入口。
- 週報後續可引用同一組 plan summary，避免 AI 提示與 Dashboard 數字不一致。

## Phase 2：計畫驅動的飲食與訓練

目標：讓使用者從「看數字」進到「照計畫做」。

- 健康計畫設定頁：目標類型、期限、每週訓練次數、飲食偏好。
- 運動計畫生成改用健康計畫預設值，減少每次手動輸入；週期課表已會以每週訓練目標預填天數，並把個人檔案的訓練經驗（初學者／中階／進階）帶進 AI 規劃 prompt。
- 依照今日缺口產生飲食建議，例如蛋白質不足、熱量接近超標、晚餐調整；Meals 頁已會依健康計畫顯示下一餐熱量與蛋白質建議。

## Phase 3：食物資料庫與照片確認流程

目標：降低記餐成本，同時保留人工確認。

- 建立可搜尋的食物/食材資料庫，支援每 100g 營養素與常見份量。
- 已建立第一版可搜尋食物 catalog，提供常見份量營養素；AI 預覽確認清單與既有餐點手動修正都可搜尋並加入資料庫項目，調整克數或切換常用份量時會按比例重算營養素。
- 餐點照片辨識後已先進入 AI 預覽確認流程，使用者可在確認清單內調整食物、克數與營養素後再寫入餐點日誌。
- 常用餐點與最近餐點已可快速複製到今日；下一步可與食物資料庫項目重組，減少 AI 重複估算。

## Phase 4：週報進階化與成就系統

目標：把回顧變成可行動的建議。

- 週報已加入達標率：熱量控制、蛋白質、訓練次數、記錄天數（`GET /reports/weekly` 回傳 `adherence`，並注入 AI grounded context；Dashboard 週報卡以進度條呈現）。
- 週報已加入趨勢偵測：蛋白質偏低、記錄天數不足（本週數字）、訓練量下降、體重停滯（與上週比較，跨週訊號僅在兩週皆完整時觸發）、肌肉量上升／體脂下降（本週體組成正向變化，有量測時）；結果回傳於 `trends`，並注入 AI grounded context 讓建議優先回應這些重點。
- 成就系統已新增照片記餐（PHOTO_5 / PHOTO_25）、週訓練目標達成（WEEKLY_GOAL_1 / WEEKLY_GOAL_4）與每日習慣連續達成（HABIT_7 / HABIT_30）徽章；徽章牆由 `StreakCard` 動態渲染含進度條。訓練課表完成徽章待後續（需課表完成定義）。

## Phase 5：AI Coach 整合

目標：讓 AI 回答基於同一份健康計畫。

- AI 助理（Chat）已注入 Health Plan context：在系統 prompt 帶入就緒分數與 `nextActions` 優先事項，使用者問「今天該做什麼」時據此回答，與 Dashboard 同源；weekly report 已注入達標率與趨勢，workout schedule context 待後續。
- AI 已可根據 `nextActions` 解釋今日優先事項（Chat 已串接；其餘入口陸續整合）。
- 食物資料庫已接上今日營養缺口：`GET /foods/suggestions` 依 `GET /stats/budget` 的剩餘熱量與蛋白質缺口，從 catalog 推薦具體食物（常見份量、決定性、無需 AI），Meals 頁「下一餐建議」卡會列出推薦食物。
- Vision/文字 meal preview 已與 food database 結合：AI 負責辨識食物與克數，命中 catalog 的項目改以資料庫每 100g 基準按克數重算營養素（取最長名稱的最精確匹配），未命中維持 AI 估值；使用者仍可在確認清單調整。
